Q1 · Algorithms, data structures and arrays

Q.1 (a) Define Algorithm. List out characteristics of algorithm.3 marks

Question as printed: Q.1 (a) Define Algorithm. List out characteristics of algorithm.

An algorithm is a finite, ordered sequence of unambiguous steps for solving a problem or performing a computation. It is independent of any one programming language.

Characteristics:

  • Input: accepts zero or more clearly specified inputs.
  • Output: produces at least one result.
  • Definiteness: every instruction is precise and unambiguous.
  • Finiteness: it terminates after a finite number of steps.
  • Effectiveness: each operation is basic and can be carried out in finite time.
  • Generality: it solves every valid instance of the stated problem, not just one example.

Question as printed: Q.1 (b) Explain Primitive and non-primitive types of data structures.

A data structure organizes data so it can be stored, accessed and processed efficiently.

TypeMeaningExamples

Q.1 (c) Explain Binary search method with suitable example. Write down Binary search algorithm for searching an element in array.7 marks

Question as printed: Q.1 (c) Explain Binary search method with suitable example. Write down Binary search algorithm for searching an element in array.

Binary search locates a key in a sorted array by comparing it with the middle element and discarding the half that cannot contain the key. It repeats until the key is found or the interval is empty. The array must be sorted; with each iteration the search interval is halved, so time is O(log n) and iterative space is O(1).

Example: search for 30 in A = [5, 10, 15, 20, 25, 30, 35, 40, 45] (indices start at zero):

lowhighmid = ⌊(low+high)/2⌋A[mid]Action
0842530 > 25; low = 5
5863530 < 35; high = 5
55530Found at index 5 (position 6)
Iterative algorithm

BINARY_SEARCH(A, n, key)
    low  ← 0
    high ← n - 1
    while low ≤ high
        mid ← low + floor((high - low) / 2)
        if A[mid] = key
            return mid
        else if A[mid] < key
            low ← mid + 1
        else
            high ← mid - 1
    return NOT_FOUND

If duplicates exist, this version may return any matching occurrence. To use binary search, the data must be sorted in the same order assumed by the comparisons.

Q.1 (c) OR Define array. Explain row major and column major array with the help of an example.7 marks

Question as printed: Q.1 (c) OR Define array. Explain row major and column major array with the help of an example.

An array is a collection of same-type elements stored in contiguous memory and accessed using an index. A two-dimensional array is a table of rows and columns.

For a row-major array A with M rows and N columns, zero-based indices and element width w:

LOC(A[i][j]) = Base(A) + w(iN + j)

For column-major storage:

LOC(A[i][j]) = Base(A) + w(jM + i)

Example: A is 3 × 4, Base(A)=1000, w=2 bytes. For A[1][2], row-major offset is 2(1×4+2)=12 bytes, so address 1012. Column-major offset is 2(2×3+1)=14 bytes, so address 1014. C stores multidimensional arrays in row-major order.

Storage orderSequence of locations for A[3][4]
Row-majorA[0][0], A[0][1], A[0][2], A[0][3], A[1][0], … (complete one row at a time).
Column-majorA[0][0], A[1][0], A[2][0], A[0][1], A[1][1], … (complete one column at a time).

Q2 · Stacks, expressions and queues

Q.2 (a) Define Stack. Write an algorithm to push an element into the stack.3 marks

Question as printed: Q.2 (a) Define Stack. Write an algorithm to push an element into the stack.

A stack is a linear data structure that follows LIFO (Last In, First Out): the most recently pushed element is the first one popped. Both insertion (PUSH) and deletion (POP) occur at the top. In an array implementation with zero-based indexing, an empty stack has TOP = −1.

PUSH must detect overflow before changing the stack:

Pseudocode

PUSH(STACK, MAX, TOP, ITEM)
    if TOP = MAX - 1
        report OVERFLOW
        return TOP
    TOP ← TOP + 1
    STACK[TOP] ← ITEM
    return TOP

Q.2 (b) Convert the following infix expression into postfix expression: A*(B+D)/E-F*(G+H/K)4 marks

Question as printed: Q.2 (b) Convert the following infix expression into postfix expression: A*(B+D)/E-F*(G+H/K)

In postfix form, each operator follows its operands. Parentheses control grouping; multiplication and division are evaluated before subtraction, with equal-precedence operators processed left to right.

Convert the parenthesized expressions first: (B+D) → BD+ and (G+H/K) → GHK/+ (H/K is formed before the addition). Thus A*(B+D)/E → ABD+*E/, F*(G+H/K) → FGHK/+*; subtract the second from the first:

Postfix: ABD+*E/FGHK/+*-

Check the parse: (((A × (B+D)) ÷ E) − (F × (G + (H ÷ K)))).

Q.2 (c) Write applications of stack. Explain recursion with the help of an example.7 marks

Question as printed: Q.2 (c) Write applications of stack. Explain recursion with the help of an example.

Applications of a stack: function calls and recursion; infix-to-postfix/prefix conversion and expression evaluation; parenthesis matching; reversing data; undo/redo; browser history; backtracking and depth-first search.

Recursion is a method in which a function calls itself on a smaller subproblem. Every recursive solution needs a base case to stop and a progress step that moves toward it. Function calls are stored on the run-time call stack.

Factorial example: n! = n × (n−1)! for n>1, and 0! = 1:

C example

int factorial(int n) {
    if (n < 0) return -1;       // invalid input
    if (n <= 1) return 1;       // base case
    return n * factorial(n - 1);
}
// factorial(4) = 4 * 3 * 2 * 1 = 24

For factorial(4), calls descend 4 → 3 → 2 → 1; the base case returns 1 and the pending calls multiply on the way back, giving 24.

Q.2 (a) OR Write an algorithm to delete an element from simple queue.3 marks

Question as printed: Q.2 (a) OR Write an algorithm to delete an element from simple queue.

Assume a linear array queue Q[0…MAX−1] with FRONT=REAR=−1 when empty. Deletion removes the element at FRONT. The single-element case resets both pointers; otherwise FRONT advances by one.

Pseudocode

DEQUEUE(Q, FRONT, REAR)
    if FRONT = -1
        report UNDERFLOW
        return
    ITEM ← Q[FRONT]
    if FRONT = REAR
        FRONT ← -1
        REAR  ← -1
    else
        FRONT ← FRONT + 1
    return ITEM, FRONT, REAR

Q.2 (b) OR Differentiate between Simple Queue and Circular Queue.4 marks

Question as printed: Q.2 (b) OR Differentiate between Simple Queue and Circular Queue.

Both are FIFO (First In, First Out); they differ in how array positions are reused.

FeatureSimple (linear) queueCircular queue
Insertion / deletionInsert at REAR; delete at FRONT.Same FIFO order; pointers wrap modulo MAX.
Space reuseDeleted positions at the front are not reused without shifting.Freed positions are reused by wrapping to index 0.
Full condition (array)REAR = MAX−1, even if earlier slots are free.(REAR+1) mod MAX = FRONT.

A circular queue avoids the “false overflow” that can occur in a simple array queue after several deletions.

Question as printed: Q.3 (b) Give difference between singly linked list and doubly linked list.

A singly linked list stores one forward link per node; a doubly linked list stores both backward and forward links.

Q.3 (c) Develop an algorithm to insert a new node in sorted linked list.7 marks

Question as printed: Q.3 (c) Develop an algorithm to insert a new node in sorted linked list.

Assume the list is sorted in ascending order and each node has fields data and next. Allocate and fill a new node, then insert at the head if the list is empty or the new value belongs before the current head. Otherwise stop at the node whose successor is the first value ≥ x (or NULL).

Ascending-order linked-list algorithm

INSERT_SORTED(START, x)
    new ← allocate Node
    if new = NULL
        report ALLOCATION_FAILURE
        return START
    new.data ← x

    if START = NULL or x ≤ START.data
        new.next ← START
        START ← new
        return START

    ptr ← START
    while ptr.next ≠ NULL and ptr.next.data < x
        ptr ← ptr.next

    new.next ← ptr.next
    ptr.next ← new
    return START

Example: 10 → 20 → 30 → 40; insert 25 after 20 and before 30 to obtain 10 → 20 → 25 → 30 → 40. The traversal is O(n); the link changes are O(1).

Q.3 (b) Explain the concept of Circular linked list with example.4 marks

Question as printed: Q.3 (b) Explain the concept of Circular linked list with example.

In a circular linked list, the link of the last node points back to the first node instead of NULL. A singly circular list may be represented by a head pointer (or a tail pointer whose next field is the head).

Example: A → B → C → A. Starting at A and following next visits B, C, then returns to A. A traversal must stop when it reaches the starting node again; checking for NULL would never terminate.

Circular lists are useful for round-robin scheduling, circular playlists and repeated-turn simulations. In an empty list, the head is NULL; a one-node circular list has node.next pointing to itself.

Q.3 (c) Develop an algorithm to insert a new node at the end of singly linked list.7 marks

Question as printed: Q.3 (c) Develop an algorithm to insert a new node at the end of singly linked list.

Allocate a node, store the new value and set its next pointer to NULL. If the list is empty, the new node becomes the head. Otherwise traverse to the node whose next pointer is NULL and link it to the new node.

Singly linked-list algorithm

INSERT_END(START, x)
    new ← allocate Node
    if new = NULL
        report ALLOCATION_FAILURE
        return START
    new.data ← x
    new.next ← NULL

    if START = NULL
        START ← new
        return START

    ptr ← START
    while ptr.next ≠ NULL
        ptr ← ptr.next
    ptr.next ← new
    return START

For example, 10 → 20 → 30 becomes 10 → 20 → 30 → x. This algorithm takes O(n) time; if a tail pointer is maintained, insertion can be O(1).

Q4 · Trees and graphs

Q.4 (a) Define following terms of Tree Data structure. i) Complete binary tree ii) Root node iii) out-degree3 marks

Question as printed: Q.4 (a) Define following terms of Tree Data structure. i) Complete binary tree ii) Root node iii) out-degree

  • Complete binary tree: a binary tree in which every level except possibly the last is completely filled, and nodes on the last level occupy the leftmost positions (there are no gaps before a last-level node).
  • Root node: the unique topmost node of a non-empty tree; it has no parent.
  • Out-degree: the number of edges leaving a vertex/node. In a rooted tree this is the number of its children; in a binary tree it is 0, 1 or 2.

Do not confuse a complete binary tree with a full binary tree (each node has either zero or two children) or a perfect binary tree (all levels are full).

Question as printed: Q.4 (a) OR Define following terms of Graph Data structure. i) Vertex ii) Edge iii) Path

  • Vertex (node): a basic object/entity in a graph; the set of vertices is denoted V.

Q.4 (c) OR Explain deletion of a node from binary search tree with an example.7 marks

Question as printed: Q.4 (c) OR Explain deletion of a node from binary search tree with an example.

Search for the key as in BST search, then handle one of three cases:

  1. Leaf: remove it and set its parent link to NULL.
  2. One child: connect the parent directly to the node’s only child; the child takes its place.
  3. Two children: find the in-order successor (smallest node in the right subtree) or predecessor (largest in the left subtree), copy its value into the node, then delete that successor/predecessor, which has at most one child.

For example, delete 50 from a BST whose right subtree contains 70 with left child 60 and 60 has left child 55. The successor of 50 is 55. Replace 50 by 55, then remove the original 55 leaf (or link its parent to its child if it has one). The BST ordering is preserved.

Deletion runs in O(h), where h is tree height (O(log n) for a balanced BST, O(n) in the worst case).

Recursive BST deletion

DELETE(root, key)
    if root = NULL
        return NULL
    if key < root.data
        root.left ← DELETE(root.left, key)
    else if key > root.data
        root.right ← DELETE(root.right, key)
    else
        if root.left = NULL
            temp ← root.right
            free(root)
            return temp
        if root.right = NULL
            temp ← root.left
            free(root)
            return temp
        temp ← MINIMUM(root.right)  // inorder successor
        root.data ← temp.data
        root.right ← DELETE(root.right, temp.data)
    return root

MINIMUM(node) follows left links until node.left is NULL. Always retain the returned root pointer, since deleting the root may change it.

Q.5 (b) Explain radix sort with the help of example.4 marks

Question as printed: Q.5 (b) Explain radix sort with the help of example.

Radix sort is a non-comparison sorting method for keys with a fixed number of digits. In LSD radix sort, process digits from least significant to most significant. For each digit, stably distribute values into buckets 0–9, then collect buckets in order. Stability preserves the ordering established by earlier digit passes.

Example: sort 170, 45, 75, 90, 802, 24, 2, 66 (treat missing leading digits as zero):

PassStable order after collecting buckets
Input170, 45, 75, 90, 802, 24, 2, 66
Ones170, 90, 802, 2, 24, 45, 75, 66
Tens802, 2, 24, 45, 66, 170, 75, 90
Hundreds2, 24, 45, 66, 75, 90, 170, 802

With d digit positions and n keys, the running time is O(dn) for a fixed radix (plus bucket handling); it is efficient when d is limited.

Q.5 (a) OR Define Hashing. List various hashing techniques.3 marks

Question as printed: Q.5 (a) OR Define Hashing. List various hashing techniques.

Hashing maps a key to an index in a hash table using a hash function h(key), enabling average O(1) insertion, search and deletion when the table is suitably sized and distributed.

Common hash-function techniques:

  • Division/remainder: h(k)=k mod m, often choosing m prime.
  • Mid-square: square the key and take selected middle digits/bits.
  • Folding: split the key into parts, add the parts and reduce to a table index.
  • Digit extraction/analysis: choose selected key digits that distribute well.
  • Multiplication: multiply by a constant and use a fractional part to derive an index.

When two different keys map to the same index, a collision occurs. Collision-resolution methods include separate chaining, linear probing, quadratic probing and double hashing.

Q.5 (b) Develop an algorithm for merge sort.4 marks

Question as printed: Q.5 (b) Develop an algorithm for merge sort.

Merge sort uses divide and conquer: split the array into halves until each subarray has one element, then merge adjacent sorted halves. It is stable when equal keys are taken from the left half first. Time is O(n log n); standard array merging needs O(n) auxiliary space.

Recursive algorithm and merge step

MERGE_SORT(A, left, right)
    if left < right
        mid ← floor((left + right) / 2)
        MERGE_SORT(A, left, mid)
        MERGE_SORT(A, mid + 1, right)
        MERGE(A, left, mid, right)

MERGE(A, left, mid, right)
    copy A[left..mid] to L
    copy A[mid+1..right] to R
    i ← 0; j ← 0; k ← left
    while i < length(L) and j < length(R)
        if L[i] ≤ R[j]
            A[k] ← L[i]; i ← i + 1
        else
            A[k] ← R[j]; j ← j + 1
        k ← k + 1
    while i < length(L)
        A[k] ← L[i]; i ← i + 1; k ← k + 1
    while j < length(R)
        A[k] ← R[j]; j ← j + 1; k ← k + 1

Call MERGE_SORT(A, 0, n−1). The recursion depth is O(log n), and each level merges O(n) elements.
