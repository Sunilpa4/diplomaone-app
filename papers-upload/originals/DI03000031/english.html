Q1 · Database terminology and SELECT queries

Q.1 (a) Define Data Dictionary and Metadata.3 marks

Question as printed: Q.1 (a) Define Data Dictionary and Metadata.

Metadata means “data about data”: information that describes the structure, meaning, source, format or constraints of stored data. Examples include a column name, data type, key, default and permitted values.

A data dictionary is the DBMS-maintained collection of metadata about a database. It records definitions and properties of schemas, tables, columns, views, indexes, users, privileges and constraints. Oracle exposes dictionary information through views such as USER_TABLES, USER_TAB_COLUMNS and USER_CONSTRAINTS.

Metadata is the information; the data dictionary is an organized repository in which the DBMS stores and presents much of that information.

Q.1 (b) Explain Select Query Command with Example.4 marks

Question as printed: Q.1 (b) Explain Select Query Command with Example.

SELECT is the SQL query command used to retrieve data from one or more tables or views. It can choose columns, filter rows, form groups and order the result. A basic form is:

Oracle SQL / PL/SQL

SELECT [DISTINCT] column_list
FROM table_name
[WHERE row_condition]
[GROUP BY group_columns]
[HAVING group_condition]
[ORDER BY sort_columns [ASC | DESC]];

Example: retrieve the names and cities of customers in Vadodara:

Oracle SQL / PL/SQL

SELECT Cname, CCity
FROM Customer
WHERE CCity = 'Vadodara'
ORDER BY Cname;

The query returns matching rows without changing the stored table. Use * to select all columns, although naming required columns is usually clearer.

Q2 · SQL commands and operators

Q.2 (a) List DML Commands and Explain any One with Example.3 marks

Question as printed: Q.2 (a) List DML Commands and Explain any One with Example.

DML (Data Manipulation Language) commands manipulate table rows. Common commands are INSERT (add rows), UPDATE (change rows), DELETE (remove rows) and MERGE (insert or update based on a match). Many introductory classifications list SELECT with DML; it is also commonly separated as DQL because it retrieves rather than changes rows.

UPDATE example: set C001’s city to Vadodara:

Oracle SQL / PL/SQL

UPDATE Customer
SET CCity = 'Vadodara'
WHERE Cno = 'C001';

-- Check the changed row
SELECT Cno, Cname, CCity
FROM Customer
WHERE Cno = 'C001';

COMMIT;

Without the WHERE condition, all rows would be updated.

Q.2 (b) Explain Relational Operators in SQL.4 marks

Question as printed: Q.2 (b) Explain Relational Operators in SQL.

Relational (comparison) operators compare two values or expressions in a condition. The condition evaluates to TRUE, FALSE or UNKNOWN (for example, comparisons involving NULL).

OperatorMeaningExample
=Equal toCCity = 'Vadodara'

Examples in a WHERE clause:

Oracle SQL / PL/SQL

SELECT Cname FROM Customer WHERE Cno <> 'C001';
SELECT Cname FROM Customer WHERE CCity = 'Vadodara';

Use IS NULL or IS NOT NULL to test NULL; = NULL is not a valid null test. SQL also offers special predicates such as BETWEEN, IN and LIKE, and logical operators AND, OR and NOT.

Q.2 (c) Define View, List Types of Views and Explain it by using example.7 marks

Question as printed: Q.2 (c) Define View, List Types of Views and Explain it by using example.

A view is a named query that presents selected columns and rows as a virtual table. A conventional view stores its definition, not a separate copy of its result; it can simplify queries and restrict the data exposed to users.

Common types: a simple view is based on one base table and has no group functions; it may be updatable subject to Oracle’s rules. A complex view uses joins, expressions, group functions or GROUP BY and is generally not directly updatable. A materialized view stores a query result and is refreshed to reflect source changes.

Example: create a simple view showing only Vadodara customer names and areas:

Oracle SQL / PL/SQL

CREATE OR REPLACE VIEW Vadodara_Customers AS
SELECT Cno, Cname, CArea, CCity
FROM Customer
WHERE CCity = 'Vadodara';

SELECT Cname, CArea
FROM Vadodara_Customers;

The view definition is saved; when queried, Oracle evaluates it against Customer. A complex-view example may join customer and order tables or aggregate by city.

Q.2 (a) OR List TCL Commands and Explain any One with Example.3 marks

Question as printed: Q.2 (a) OR List TCL Commands and Explain any One with Example.

TCL (Transaction Control Language) commands manage transaction boundaries. The principal commands are COMMIT, ROLLBACK and SAVEPOINT; Oracle also provides SET TRANSACTION for transaction properties.

ROLLBACK undoes uncommitted DML in the current transaction, or undoes changes back to a named savepoint:

Oracle SQL / PL/SQL

UPDATE Customer
SET CCity = 'Surat'
WHERE Cno = 'C001';

SAVEPOINT before_correction;
UPDATE Customer
SET CCity = 'Vadodara'
WHERE Cno = 'C001';

ROLLBACK TO before_correction; -- undo the second update
ROLLBACK; -- undo remaining uncommitted work

COMMIT makes pending transaction changes permanent. DDL statements in Oracle perform implicit commits.

Q.2 (b) OR Explain IN Operators in SQL.4 marks

Question as printed: Q.2 (b) OR Explain IN Operators in SQL.

IN tests whether an expression matches any value in a specified list or the result of a subquery. It is a concise alternative to several equality conditions joined by OR. NOT IN tests non-membership; NULL values require care because SQL uses three-valued logic.

Oracle SQL / PL/SQL

-- Equivalent to CCity = 'Ahmedabad' OR CCity = 'Vadodara'
SELECT Cname, CCity
FROM Customer
WHERE CCity IN ('Ahmedabad', 'Vadodara');

-- IN with a subquery
SELECT Cname
FROM Customer
WHERE CCity IN (
SELECT CCity
FROM Preferred_Cities
);

The first query selects customers in either listed city. Avoid a NULL in a NOT IN subquery unless its effect is explicitly handled.

Q.2 (c) OR List Types of Index and Explain How Can We Create an Index by using example.7 marks

Question as printed: Q.2 (c) OR List Types of Index and Explain How Can We Create an Index by using example.

An index is a database structure that helps locate table rows without scanning every row. Indexes can improve selective searches and joins, but use storage and add work to INSERT, UPDATE and DELETE.

Common classifications include unique and non-unique indexes; single-column and composite (multiple-column) indexes; and, in Oracle, B-tree (the default) and bitmap index structures. Function-based indexes store an expression such as UPPER(Cname).

Create a non-unique B-tree index to speed searches by city:

Oracle SQL / PL/SQL

CREATE INDEX idx_customer_city
ON Customer (CCity);

-- Composite index example
CREATE INDEX idx_customer_city_area
ON Customer (CCity, CArea);

-- Remove an index when no longer needed
DROP INDEX idx_customer_city_area;

The column order matters in a composite index: (CCity, CArea) is most directly useful for filters beginning with CCity.

Q3 · SQL functions, grouping and joins

Q.3 (a) List Date Functions and Explain any two Date Functions.3 marks

Question as printed: Q.3 (a) List Date Functions and Explain any two Date Functions.

Oracle date functions include SYSDATE, ADD_MONTHS, MONTHS_BETWEEN, NEXT_DAY, LAST_DAY, ROUND and TRUNC.

  • ADD_MONTHS(date, n) returns the date n months before or after the given date.
  • LAST_DAY(date) returns the final calendar day of the date’s month.
Oracle SQL / PL/SQL

SELECT ADD_MONTHS(DATE '2026-05-18', 2) AS after_two_months,
LAST_DAY(DATE '2026-05-18') AS month_end
FROM dual;
-- after_two_months = 18-JUL-2026; month_end = 31-MAY-2026

Oracle DATE values include a time component; format them for display with TO_CHAR when a specific text format is required.

Q.3 (b) List Character Functions and Explain any two Character Functions.4 marks

Question as printed: Q.3 (b) List Character Functions and Explain any two Character Functions.

Oracle character functions include UPPER, LOWER, INITCAP, LENGTH, SUBSTR, INSTR, CONCAT, REPLACE, TRIM, LPAD and RPAD.

  • UPPER(char) returns the text with letters converted to uppercase.
  • SUBSTR(char, start, length) returns a substring. Oracle character positions are one-based; a negative start counts from the end.
Oracle SQL / PL/SQL

SELECT UPPER('Vadodara') AS city_upper,
SUBSTR('DATABASE', 2, 4) AS part
FROM dual;
-- VADODARA ATAB

These functions return values that can be displayed, filtered, grouped or used in expressions; they do not change the stored value unless used in an UPDATE.

Q.3 (c) Explain Group by and Having Clause with example.7 marks

Question as printed: Q.3 (c) Explain Group by and Having Clause with example.

GROUP BY combines rows with the same value(s) in the grouping columns so aggregate functions such as COUNT, SUM, AVG, MIN and MAX can be calculated for each group. HAVING filters groups after aggregation; WHERE filters individual rows before grouping.

Count customers per city and show only cities with at least two customers:

Oracle SQL / PL/SQL

SELECT CCity, COUNT(*) AS CustomerCount
FROM Customer
GROUP BY CCity
HAVING COUNT(*) >= 2
ORDER BY CCity;

Result for the supplied rows:

CCityCustomerCount
Ahmedabad3
Vadodara2

Every selected non-aggregate expression must be included in GROUP BY in Oracle.

Q.3 (a) OR List Numeric Functions and Explain any two Numeric Functions.3 marks

Question as printed: Q.3 (a) OR List Numeric Functions and Explain any two Numeric Functions.

Oracle numeric functions include ABS, CEIL, FLOOR, ROUND, TRUNC, MOD, POWER and SQRT.

  • ROUND(n, d) rounds n to d decimal places (or to the nearest integer if d is omitted).
  • MOD(m, n) returns the remainder after dividing m by n.
Oracle SQL / PL/SQL

SELECT ROUND(123.456, 2) AS rounded_value,
MOD(17, 5) AS remainder
FROM dual;
-- 123.46, 2

For a negative d, ROUND rounds to a place left of the decimal point. TRUNC removes digits without rounding.

Q.3 (b) OR List Conversion Functions and Explain any two Conversion Functions.4 marks

Question as printed: Q.3 (b) OR List Conversion Functions and Explain any two Conversion Functions.

Oracle conversion functions include TO_CHAR, TO_DATE and TO_NUMBER. Explicit conversion avoids relying on session-dependent implicit conversions.

  • TO_CHAR(value, format) converts a number or date to formatted character data.
  • TO_DATE(text, format) converts character text to a DATE; the format should match the input.
  • TO_NUMBER(text, format) converts numeric text to NUMBER.
Oracle SQL / PL/SQL

SELECT TO_CHAR(DATE '2026-05-18', 'DD-MON-YYYY') AS date_text,
TO_DATE('18-05-2026', 'DD-MM-YYYY') AS date_value,
TO_NUMBER('1234.50', '9999.99') AS amount
FROM dual;

TO_CHAR controls display; TO_DATE and TO_NUMBER create typed values suitable for date and arithmetic operations.

Q.3 (c) OR Explain Inner Join with Example7 marks

Question as printed: Q.3 (c) OR Explain Inner Join with Example

An INNER JOIN returns rows for which the join condition matches in both tables; rows without a match are omitted. An explicit ON clause identifies related columns and keeps the condition readable.

Example: list employees with their department names (assume Employee.DeptID references Department.DeptID):

Oracle SQL / PL/SQL

SELECT e.EmpName, d.DeptName
FROM Employee e
INNER JOIN Department d
ON e.DeptID = d.DeptID;

If an employee has no matching department, that employee does not appear in this result. A primary-key/foreign-key relationship is a common basis for the join.

Q4 · Keys, constraints and normalization

Q.4 (a) Differentiate Primary Key and Foreign Key3 marks

Question as printed: Q.4 (a) Differentiate Primary Key and Foreign Key

A primary key identifies each row in its own table. A foreign key references a candidate/primary key in another (or the same) table to preserve a valid relationship.

Example: Customer.Cno is a primary key; Orders.Cno may be a foreign key that references Customer(Cno).

Q.4 (b) Explain NOT NULL Constraints with Example.4 marks

Question as printed: Q.4 (b) Explain NOT NULL Constraints with Example.

A NOT NULL constraint requires a column to contain a value in every row. Oracle rejects an INSERT or UPDATE that would leave the constrained column NULL. It may be declared at column level when creating a table, or added later if existing rows satisfy the rule.

Oracle SQL / PL/SQL

CREATE TABLE Student (
StudentID NUMBER CONSTRAINT pk_student PRIMARY KEY,
StudentName VARCHAR2(50)
CONSTRAINT nn_student_name NOT NULL
);

-- Later, on an existing table (no NULL names may remain)
ALTER TABLE Student
MODIFY (StudentName CONSTRAINT nn_student_name NOT NULL);

An empty character string in Oracle is treated as NULL. A NOT NULL constraint does not by itself require a column to be unique; use UNIQUE or PRIMARY KEY for that rule.

Q.4 (c) Define Normalization, Explain 3NF with Example.7 marks

Question as printed: Q.4 (c) Define Normalization, Explain 3NF with Example.

Normalization is the process of organizing relations and their dependencies to reduce redundant data and prevent insertion, update and deletion anomalies.

A relation is in Third Normal Form (3NF) if it is already in 2NF and no non-key attribute depends transitively on a candidate key. Equivalently, for every non-trivial functional dependency X → A, either X is a superkey or A is a prime attribute (part of some candidate key).

Example relation:

StuID (PK)StuNameDeptIDDeptName
101AshaD01Computer
102RaviD01Computer
103MinaD02Electrical

Assume StuID → StuName, DeptID and DeptID → DeptName. Thus StuID → DeptID → DeptName is a transitive dependency: DeptName depends on a non-key DeptID rather than directly on the student key. Decompose into:

STUDENTDEPARTMENT
(StuID PK, StuName, DeptID FK)(DeptID PK, DeptName)

Now STUDENT(StuID, StuName, DeptID) stores student facts, and DEPARTMENT(DeptID, DeptName) stores each department name once. The decomposition is lossless because DeptID is the key of DEPARTMENT; the transitive dependency is removed.

Q.4 (a) OR Explain CHECK Constraints with Example.3 marks

Question as printed: Q.4 (a) OR Explain CHECK Constraints with Example.

A CHECK constraint enforces a Boolean condition on each inserted or updated row. The condition must be TRUE or UNKNOWN to pass Oracle’s check; add NOT NULL as well when a value is required.

Oracle SQL / PL/SQL

CREATE TABLE Product (
ProductID NUMBER PRIMARY KEY,
ProductName VARCHAR2(50) NOT NULL,
Price NUMBER(8,2)
CONSTRAINT ck_product_price CHECK (Price >= 0),
Status CHAR(1)
CONSTRAINT ck_product_status CHECK (Status IN ('A', 'I'))
);

Oracle evaluates the constraint for each row. A CHECK constraint is suitable for same-row rules such as non-negative price or a value from an allowed set.

Q.4 (b) OR Explain On Delete Cascade with Example.4 marks

Question as printed: Q.4 (b) OR Explain On Delete Cascade with Example.

ON DELETE CASCADE is a foreign-key option. When a referenced parent row is deleted, Oracle automatically deletes child rows that reference it. Use it only when child records should not survive independently of the parent.

Oracle SQL / PL/SQL

CREATE TABLE Department (
DeptID NUMBER PRIMARY KEY,
DeptName VARCHAR2(40) NOT NULL
);

CREATE TABLE Employee (
EmpID NUMBER PRIMARY KEY,
EmpName VARCHAR2(40) NOT NULL,
DeptID NUMBER,
CONSTRAINT fk_emp_dept FOREIGN KEY (DeptID)
REFERENCES Department (DeptID)
ON DELETE CASCADE
);

DELETE FROM Department WHERE DeptID = 10;
-- Employee rows with DeptID = 10 are deleted automatically.

Without ON DELETE CASCADE, Oracle prevents deleting a parent key that is still referenced (unless the child reference is first removed). A cascading delete can affect many rows, so verify the parent selection before executing it.

Q.4 (c) OR Define Normalization, Explain 2NF with Example.7 marks

Question as printed: Q.4 (c) OR Define Normalization, Explain 2NF with Example.

Normalization organizes relational data to reduce duplication and anomalies. A relation is in Second Normal Form (2NF) when it is in 1NF and every non-prime attribute is fully functionally dependent on the whole of every candidate key—not on only part of a composite key. A relation whose candidate keys each contain one attribute is automatically free of partial-key dependencies.

Consider ENROLLMENT(StudentID, CourseID, StudentName, CourseName, Grade), with composite key (StudentID, CourseID). Assume:

  • (StudentID, CourseID) → Grade
  • StudentID → StudentName (partial dependency)
  • CourseID → CourseName (partial dependency)

StudentName and CourseName depend on only part of the composite key, so the relation is not in 2NF. Decompose it into:

RelationAttributes and key
STUDENTStudentID (PK), StudentName
COURSECourseID (PK), CourseName
ENROLLMENTStudentID (PK, FK), CourseID (PK, FK), Grade

In each resulting relation, non-key attributes depend on the whole key. The decomposition removes the partial dependencies while retaining the enrollment grade for each student-course pair.

Q5 · PL/SQL and triggers

Q.5 (a) Explain PL/SQL Block Structure.3 marks

Question as printed: Q.5 (a) Explain PL/SQL Block Structure.

PL/SQL is Oracle’s procedural extension to SQL. A PL/SQL block is the basic program unit. Its sections are:

  • DECLARE (optional): variables, constants, cursors and local exceptions.
  • BEGIN … END (required): executable SQL and procedural statements.
  • EXCEPTION (optional): handlers for run-time errors raised in the executable section.
Oracle SQL / PL/SQL

DECLARE -- optional declaration section
v_message VARCHAR2(30) := 'Hello';
BEGIN -- required executable section
DBMS_OUTPUT.PUT_LINE(v_message);
EXCEPTION -- optional error handlers
WHEN OTHERS THEN
DBMS_OUTPUT.PUT_LINE('An error occurred');
END;
/ -- client terminator, not PL/SQL syntax

PL/SQL keywords are not case-sensitive. A slash on a line by itself tells tools such as SQL*Plus to execute the completed block.

Q.5 (b) Write PL/SQL Block to find whether the given no is even or odd.4 marks

Question as printed: Q.5 (b) Write PL/SQL Block to find whether the given no is even or odd.

Assume the input is an integer. The remainder when divided by 2 is zero for an even integer and non-zero for an odd integer. In SQL*Plus or SQL Developer script mode, &num prompts for a value.

Oracle SQL / PL/SQL

SET SERVEROUTPUT ON;
DECLARE
v_num NUMBER := &num;
BEGIN
IF MOD(v_num, 2) = 0 THEN
DBMS_OUTPUT.PUT_LINE(v_num || ' is even');
ELSE
DBMS_OUTPUT.PUT_LINE(v_num || ' is odd');
END IF;
END;
/

Example: entering 14 displays “14 is even”; entering 9 displays “9 is odd”.

Q.5 (c) Define Trigger, Explain it with example.7 marks

Question as printed: Q.5 (c) Define Trigger, Explain it with example.

A trigger is a stored PL/SQL program unit that runs automatically when a specified database event occurs. A trigger may fire BEFORE or AFTER a DML statement, or INSTEAD OF operations on a view; it may be statement-level or FOR EACH ROW. Oracle also supports DDL and database/system-event triggers.

Example: automatically store a customer name in uppercase before each insert or name update. In a row-level trigger, :NEW refers to the new row values.

Oracle SQL / PL/SQL

CREATE OR REPLACE TRIGGER trg_customer_name_upper
BEFORE INSERT OR UPDATE OF Cname ON Customer
FOR EACH ROW
BEGIN
:NEW.Cname := UPPER(:NEW.Cname);
END;
/

The trigger executes as part of the triggering statement; it is not called explicitly. A trigger should be used for rules that genuinely belong at the database boundary, since hidden side effects can make operations harder to reason about.

Q.5 (a) OR Explain IF…. THEN Statement in PL/SQL.3 marks

Question as printed: Q.5 (a) OR Explain IF…. THEN Statement in PL/SQL.

The PL/SQL IF … THEN statement tests a Boolean condition. If the condition is TRUE, the statements between THEN and END IF execute. An optional ELSIF adds further conditions; an optional ELSE handles all remaining cases.

Oracle SQL / PL/SQL

IF condition THEN
statements;
ELSIF another_condition THEN
statements;
ELSE
statements;
END IF;

Example:

Oracle SQL / PL/SQL

DECLARE
v_marks NUMBER := 72;
BEGIN
IF v_marks >= 35 THEN
DBMS_OUTPUT.PUT_LINE('Pass');
ELSE
DBMS_OUTPUT.PUT_LINE('Fail');
END IF;

Q.5 (b) Write PL/SQL block to find the sum of digit of entered number e.g., 1234=1+2+3+4=104 marks

Question as printed: Q.5 (b) Write PL/SQL block to find the sum of digit of entered number e.g., 1234=1+2+3+4=10

Take the last digit with MOD, add it to a running total, then remove that digit with TRUNC(number/10). ABS lets the block handle a negative input; zero produces a sum of zero.

Oracle SQL / PL/SQL

SET SERVEROUTPUT ON;
DECLARE
v_num NUMBER := &num;
v_work NUMBER := ABS(TRUNC(v_num));
v_digit NUMBER;
v_sum NUMBER := 0;
BEGIN
WHILE v_work > 0 LOOP
v_digit := MOD(v_work, 10);
v_sum := v_sum + v_digit;
v_work := TRUNC(v_work / 10);
END LOOP;
DBMS_OUTPUT.PUT_LINE('Sum of digits = ' || v_sum);
END;
/

For input 1234, the digits add as 1+2+3+4, so the output is Sum of digits = 10.

Q.5 (c) OR Define Function in PL/SQL, Explain it with Example7 marks

Question as printed: Q.5 (c) OR Define Function in PL/SQL, Explain it with Example

A PL/SQL function is a named stored program unit that returns exactly one value using a RETURN datatype and a RETURN statement. It can accept IN parameters and can be called from PL/SQL or, subject to SQL-callability rules, from a SQL statement.

Example: return annual pay when the input is monthly pay:

Oracle SQL / PL/SQL

CREATE OR REPLACE FUNCTION annual_salary (
p_monthly_salary IN NUMBER
) RETURN NUMBER
IS
BEGIN
RETURN p_monthly_salary * 12;
END annual_salary;
/

-- Example call from SQL
SELECT annual_salary(5000) AS yearly_salary
FROM dual;
-- result: 60000

The function’s formal parameter is local to the function. The returned value has the declared NUMBER type.
